# 合约数据获取与独立服务方案

## Context

用户希望接入 Binance 合约（USDⓈ-M Futures）数据(ETHUSDT)，用于后续合约策略跟进。核心要求：
1. **现货与合约完全独立** —— 不在现货策略上直接改为合约策略
2. **数据源可切换** —— 后续换数据源不用大改代码（配置化）
3. **面板可跳转** —— 通过不同 index 切换现货/合约
4. **本次先获取数据**，策略逻辑后续在合约版基础上独立优化

已验证：合约 REST API（`fapi.binance.com`）可访问，返回格式与现货完全一致（`[open_time, open, high, low, close, volume, ...]`），但价格有差异（如 21:00 K线 合约 close=1908.01 vs 现货 1908.24），证实合约数据确实不同，需要独立接入。

合约 WS 消息格式与现货一致（kline 事件，`k.c` 为最新价），解析逻辑可复用。

## 方案

### 1. 数据源配置层 `datasource.py`（新建）

集中定义现货/合约 URL，换数据源只改此文件。

```python
SPOT = {
    "name": "现货",
    "ws_kline": "wss://stream.binance.com:9443/ws/ethusdt@kline_1h",
    "ws_ticker": "wss://stream.binance.com:9443/ws/ethusdt@ticker",
    "rest_kline": "https://api.binance.com/api/v3/klines",
    "rest_ticker": "https://api.binance.com/api/v3/ticker/price?symbol=ETHUSDT",
}
FUTURES = {
    "name": "合约",
    "ws_kline": "wss://fstream.binance.com/ws/ethusdt@kline_1h",
    "ws_ticker": "wss://fstream.binance.com/ws/ethusdt@ticker",
    "rest_kline": "https://fapi.binance.com/fapi/v1/klines",
    "rest_ticker": "https://fapi.binance.com/fapi/v1/ticker/price?symbol=ETHUSDT",
}
```

### 2. 合约历史数据下载 `fetch_data_contract.py`（新建）

- 复用 [fetch_data.py](file:///q:/Program%20Files/workbuddy/2026-08-06-14-46-22/eth-quant-backtest/fetch_data.py) 的下载逻辑

- 下载到 `data/futures/ETHUSDT-1h.csv`（独立目录，不污染现货 `data/`）
- 现货 `fetch_data.py` 不动

### 3. 合约实时信号服务 `live_trader_contract.py`（新建，核心）

- 复制 [live_trader.py](file:///q:/Program%20Files/workbuddy/2026-08-06-14-46-22/eth-quant-backtest/live_trader.py) 整体结构（含本轮已修复的：定时广播、wx_notify 异步、启动容错、指标实时计算、OHLC 正确顺序、/health、前端心跳）
- 数据源用 `datasource.FUTURES`
- **端口 8081**（避免和现货 8080 冲突）
- 含 v12 信号逻辑（作为初始，后续在合约版上独立优化为合约专属策略）
- Web 面板标题标注「合约」，顶部加导航条：`[现货] | [合约]`，现货链接到 `:8080`，合约链接到当前页

仿 [run_live.bat](file:///q:/Program%20Files/workbuddy/2026-08-06-14-46-22/eth-quant-backtest/run_live.bat)，启动合约服务（8081）。
